## 11. Summary: Priority Gaps

### 🔴 Critical (Core features missing)

| # | Gap | Impact |
|---|-----|--------|
| 1 | **No real-time collaboration in Editor** | CollabService has WebSocket code but Editor doesn't use it. Zero co-editing, no live cursors, no session management UI. |
| 2 | **Plain textarea instead of code editor** | No syntax highlighting, no auto-indent, no bracket matching. Spec explicitly requires these. |
| 3 | **No project member management UI** | Backend supports add/remove members, but there's no UI to invite or manage collaborators. |
| 4 | **No user profile page** | 5 profile features (view/edit/avatar/bio/search) have backend APIs but zero UI. |
| 5 | **Notifications don't auto-trigger** | The notification service is isolated; no other service dispatches events to it. |

### 🟡 Important (Features partially done)

| # | Gap | Impact |
|---|-----|--------|
| 6 | **Version branching has no UI** | Backend supports branches but the Editor history panel only shows "main". |
| 7 | **Snapshot tagging has no UI** | Backend supports tagging but no way to tag from the frontend. |
| 8 | **Star/fork counts not visible** | Not displayed on Explore or Dashboard project cards. |
| 9 | **Comment edit not available** | Backend PUT exists but no inline edit UI. |
| 10 | **File move/restore not wired** | Backend endpoints exist but no Editor UI. |
| 11 | **Execution history not shown** | Backend tracks all jobs but no history panel in Editor. |
| 12 | **Docker sandbox not implemented** | Uses ProcessBuilder; should use Docker for isolation. |

### 🟢 Nice to Have (Advanced features)

| # | Gap | Impact |
|---|-----|--------|
| 13 | OT/CRDT conflict resolution | Spec mentions it but complex to implement. |
| 14 | SHA-256 hash + parent snapshot chain | Git-like integrity features in version service. |
| 15 | WebSocket push for notifications | Currently polling at 30s intervals. |
| 16 | Deep-link URLs in notifications | Navigate directly to the related entity. |
| 17 | Audit logs | Platform admin audit trail. |
| 18 | Language CRUD for admin | Manage supported sandbox languages. |
| 19 | Session auto-cleanup (30 min) | Scheduled job to end inactive sessions. |
| 20 | @mention parsing in comments | Parse usernames and trigger notifications. |

## 12. Architecture Concerns

| Issue | Description |
|-------|-------------|
| **No service discovery usage** | Eureka is configured but services call each other via hardcoded URLs. |
| **No inter-service communication** | Services are isolated silos — no service calls `/notifications/send` when events occur. |
| **Database sharing** | `version-service` uses PostgreSQL (`projectdb`) while others use MySQL — this is inconsistent. |
| **CORS inconsistency** | Some services still have CORS config locally (should all be disabled, gateway-only). |
| **No API versioning** | No `/v1/` prefix on any service endpoints. |
| **Hardcoded secrets** | JWT secret and DB passwords are in `application.yml` plaintext (not in env vars or Vault). |
